# Акты определённости — Founder Mode

**Основа:** PDA Methodology v1.1, Uncertainty Map v1.1  
**Дата:** 2026-03-09

---

## Принцип (PDA)

Акт определённости — минимальное действие или сигнал, которое создаёт различие (факт) и превращает неопределённость в ясное состояние.

**Критерий качества:** акт должен быть дешёвым и не требовать избыточной когнитивной нагрузки.

---

## Поток 1: Недельное планирование (воскресенье)

### Акт 1.1 — Ответить на 6 вопросов планирования

| Поле | Значение |
|------|----------|
| **Закрываемая неопределённость** | Какой главный фокус недели? Измеримый результат — что именно? |
| **Действие** | Пользователь отвечает на 6 вопросов (where, focus, result, why_now, distractions, risk) |
| **Триггер** | Воскресенье, напоминание бота / инициатива пользователя |
| **Сигнал** | Текстовые ответы → вход для GPT |
| **Факт (результат)** | План с main_focus, weekly_result, raw_post. Сохраняется как эталон недели |
| **Стоимость** | 5–10 мин. Когнитивная: средняя (нужно сформулировать, но вопросы направляют) |
| **Механизм** | Бот задаёт вопрос за вопросом. GPT по `WEEKLY_PLAN_SYSTEM_PROMPT` возвращает структурированный план |
| **Инвариант** | План сохраняется до сбора рефлексий. Один план на неделю |

---

### Акт 1.2 — Подтвердить план

| Поле | Значение |
|------|----------|
| **Закрываемая неопределённость** | План принят как эталон? |
| **Действие** | Просмотр GPT-плана. Опционально: редактирование, подтверждение |
| **Триггер** | После генерации плана |
| **Сигнал** | План принят (явно или по умолчанию). Сохранён в weekly_plan |
| **Факт** | weekly_plan зафиксирован. Связь plan → week_id / day_range |
| **Стоимость** | <1 мин. Низкая нагрузка |
| **Механизм** | Бот показывает план. Подтверждение = сохранение. Редактирование = повторная генерация или ручное изменение |
| **Инвариант** | План привязан к day_range. Рефлексия не может относиться к будущему |

## Поток 2: Ежедневная рефлексия

### Акт 2.1 — Выбрать: было ли движение (Да/Нет)

| Поле | Значение |
|------|----------|
| **Закрываемая неопределённость** | Было ли движение сегодня по главному? |
| **Действие** | Один клик/ответ: Да или Нет |
| **Триггер** | Вечер, напоминание бота |
| **Сигнал** | had_movement: true | false |
| **Факт** | Ветка определена. Да → вопросы what_moved, sensitive_moment, tomorrow_step, thought_of_day. Нет → what_stopped, body_state, attention_sink, return_step, thought_of_day |
| **Стоимость** | <10 сек. Минимальная нагрузка — бинарный выбор |
| **Механизм** | Первый вопрос рефлексии. Ответ диктует следующие вопросы. `DAILY_REFLECTION_SYSTEM_PROMPT` |
| **Инвариант** | Одна рефлексия = один день. unique(user_id, date) |

---

### Акт 2.2 — Заполнить поля ветки (3–4 коротких ответа)

| Поле | Значение |
|------|----------|
| **Закрываемая неопределённость** | Что продвинуло? Что остановило? Как вернуться? |
| **Действие** | Краткий текстовый ответ на каждый вопрос ветки (2–3 предложения на поле) |
| **Триггер** | После выбора Да/Нет |
| **Сигнал** | what_moved / what_stopped, sensitive_moment / body_state, tomorrow_step / return_step, thought_of_day |
| **Факт** | daily_reflection с полной структурой. Сырые данные для обзора |
| **Стоимость** | 1–3 мин. Умеренная нагрузка — вопросы конкретные, ответы короткие |
| **Механизм** | Бот задаёт 3–4 вопроса подряд. Данные маппятся в `WEEKLY_REVIEW_INPUT_SCHEMA.daily_reflections[]` |
| **Инвариант** | Рефлексия привязана к дате. Идемпотентность: повтор того же дня перезаписывает |

---

### Акт 2.3 — Получить GPT-ответ на рефлексию

| Поле | Значение |
|------|----------|
| **Закрываемая неопределённость** | Рефлексия стоит времени? GPT не общие фразы? |
| **Действие** | Система вызывает GPT. Пользователь читает ответ «<День> — Рефлексия дня» |
| **Триггер** | После завершения рефлексии |
| **Сигнал** | Текст 5–8 абзацев, без советов, без пафоса |
| **Факт** | Обратная связь есть. «Ответ», не запись в пустоту. Пользователь получает фиксацию дня |
| **Стоимость** | Latency GPT ~5–15 сек. Чтение 20–40 сек |
| **Механизм** | `DAILY_REFLECTION_SYSTEM_PROMPT`. Response Contract: без советов, без эмодзи, плотно |
| **Инвариант** | Ответ генерируется один раз на рефлексию. raw_post сохраняется |

## Поток 3: Недельный обзор (суббота)

### Акт 3.1 — Проверка минимума данных

| Поле | Значение |
|------|----------|
| **Закрываемая неопределённость** | Достаточно ли данных для обзора? |
| **Действие** | Система проверяет: ≥1 план + ≥3 рефлексии в day_range |
| **Триггер** | Запрос обзора |
| **Сигнал** | Проход → формируем вход. Непроход → предупреждение «мало данных, обзор может быть неточным» |
| **Факт** | Решение: генерировать или предупредить. Инвариант: обзор не показывается без минимума (или с явным предупреждением) |
| **Стоимость** | Системная. Пользователь не действует |
| **Механизм** | Валидатор перед вызовом GPT. Проверка day_range, count(daily_reflections) |
| **Инвариант** | ≥1 план + ≥3 рефлексии |

---

### Акт 3.2 — Собрать вход по схеме

| Поле | Значение |
|------|----------|
| **Закрываемая неопределённость** | Неделя принадлежит одному циклу? |
| **Действие** | Система агрегирует day_range, weekly_plan, daily_reflections[] в `WEEKLY_REVIEW_INPUT_SCHEMA` |
| **Триггер** | После проверки минимума |
| **Сигнал** | JSON с day_range (start, end), weekly_plan (6 полей + raw_post), daily_reflections[] с полями по веткам |
| **Факт** | Структурированный вход. Все рефлексии внутри day_range. Один план на неделю |
| **Стоимость** | Системная |
| **Механизм** | Маппинг из БД/событий в схему. day_range задаёт границы |
| **Инвариант** | Рефлексии не вне day_range. План соответствует неделе |

---

### Акт 3.3 — Генерация обзора (GPT)

| Поле | Значение |
|------|----------|
| **Закрываемая неопределённость** | План vs факт: что сделал? Обзор точен? Статус результата? |
| **Действие** | GPT обрабатывает вход по `WEEKLY_REVIEW_SYSTEM_PROMPT` |
| **Триггер** | После сборки входа |
| **Сигнал** | Текст «Недельный срез»: фокус, статус (достигнут/частично/не), что сработало, узкое место, вывод |
| **Факт** | Определённость: план vs факт сжаты в смысл. Дискретный статус результата. Управленческий вывод |
| **Стоимость** | Latency GPT. Чтение 25–40 сек |
| **Механизм** | Структурированный промпт + структурированный вход. Снижает вариативность GPT |
| **Инвариант** | Вход = план + все рефлексии недели. Не выдумывать фактов |

---

### Акт 3.4 — Просмотр обзора

| Поле | Значение |
|------|----------|
| **Закрываемая неопределённость** | Пользователь видит план vs факт? |
| **Действие** | Пользователь читает обзор в Telegram |
| **Триггер** | После генерации. Бот отправляет сообщение |
| **Сигнал** | Просмотр зафиксирован (опционально: analytics) |
| **Факт** | Time-to-Wow: «Вот план. Вот факты. Вот движение.» Честная картина |
| **Стоимость** | 1–3 мин чтения |
| **Механизм** | Отправка в чат. Формат: заголовок + 5–7 абзацев |
| **Инвариант** | Обзор — информация, не приговор |

## Системные акты

### Акт S1 — Идемпотентность рефлексии

| Поле | Значение |
|------|----------|
| **Закрываемая неопределённость** | Рефлексия не дублируется? |
| **Действие** | При сохранении: проверка unique(user_id, date). Повтор = перезапись |
| **Триггер** | Submit рефлексии |
| **Сигнал** | Одна запись на пользователя на день |
| **Факт** | Нет дубликатов. Идемпотентность по ключу |
| **Механизм** | unique constraint или upsert по (user_id, date) |

---

### Акт S2 — Идемпотентность llm_call

| Поле | Значение |
|------|----------|
| **Закрываемая неопределённость** | llm_call воспроизводим? |
| **Действие** | idempotency_key при вызове. Логирование model, tokens, latency, trace_id |
| **Триггер** | Каждый вызов GPT |
| **Сигнал** | Повтор с тем же ключом не дублирует эффект. Аудит возможен |
| **Факт** | Воспроизводимость. Дедупликация при ретраях |
| **Механизм** | idempotency_key в запросе. Лог llm_calls |

---

### Акт S3 — Версионирование плана (v2)

| Поле | Значение |
|------|----------|
| **Закрываемая неопределённость** | Пользователь редактировал план? |
| **Действие** | timestamp при сохранении. Для обзора используется последняя версия |
| **Триггер** | Редактирование плана |
| **Сигнал** | Последняя версия плана в обзоре |
| **Факт** | Аудит при необходимости. v1: простая перезапись |
| **Механизм** | updated_at. v2: история версий |
