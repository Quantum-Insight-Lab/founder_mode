**Основа:** PDA Methodology v1.1, Product Spec, Invariants, Acts of Certainty  
**Дата:** 2026-03-09

---

## Принцип (PDA)

Константа — параметр, удерживающий систему в стабильном режиме: лимит, порог, коэффициент, тайм-аут.

**Рекомендации:**
- конфигурируемые (config/feature flags), но не произвольные
- для каждой: зачем нужна, что ломается без неё, как калибровать
- разделять константы продукта (UX/экономика) и надёжности (SLO, тайм-ауты, ретраи)

---

## Часть 1: Константы продукта (UX / экономика)

### CONST-001 — Порог soft/full промпта обзора

| Поле | Значение |
|------|----------|
| **Название** | MIN_REFLECTIONS_FOR_REVIEW |
| **Тип** | лимит |
| **Зачем нужна** | INV-003. Если reflections < min → soft prompt (предварительный срез), иначе полный обзор. Блокировка только при 0 рефлексий |
| **Значение по умолчанию** | 4 |
| **Допустимый диапазон** | 1–7 |
| **Как калибруем** | Эксперимент: качество soft vs full обзора, completion rate |
| **Риск, если завышена** | Чаще soft prompt → менее детальный обзор |
| **Риск, если занижена** | Чаще полный промпт на малом числе рефлексий → возможный шум |
| **Связанный инвариант** | INV-003 |
| **Владелец** | Product |

## Часть 2: Константы надёжности (SLO / инфраструктура)

### CONST-101 — Тайм-аут запроса к LLM (мс)

| Поле | Значение |
|------|----------|
| **Название** | LLM_REQUEST_TIMEOUT_MS |
| **Тип** | тайм-аут |
| **Зачем нужна** | Запросы к GPT не должны висеть бесконечно. Graceful degradation |
| **Значение по умолчанию** | 30000 (30 сек) |
| **Допустимый диапазон** | 10000–60000 |
| **Как калибруем** | p95 latency по логам llm_calls. OpenAI типично 5–15 сек |
| **Риск, если завышена** | Пользователь ждёт слишком долго |
| **Риск, если занижена** | Ложные таймауты при пиках нагрузки |
| **Владелец** | Инженерия |

---

### CONST-102 — Максимум ретраев LLM

| Поле | Значение |
|------|----------|
| **Название** | LLM_MAX_RETRIES |
| **Тип** | лимит |
| **Зачем нужна** | Transient errors (rate limit, 503). Повтор без бесконечного цикла |
| **Значение по умолчанию** | 2 |
| **Допустимый диапазон** | 1–5 |
| **Как калибруем** | Анализ transient vs permanent errors. Backoff стратегия |
| **Риск, если завышена** | Слишком долгое ожидание при перманентной ошибке |
| **Риск, если занижена** | Преждевременный отказ при временных сбоях |
| **Владелец** | Инженерия |

---

### CONST-103 — TTL idempotency key (часы)

| Поле | Значение |
|------|----------|
| **Название** | IDEMPOTENCY_KEY_TTL_HOURS |
| **Тип** | тайм-аут |
| **Зачем нужна** | INV-006. Сколько хранить результат по idempotency_key. Ретраи могут прийти с задержкой |
| **Значение по умолчанию** | 24 |
| **Допустимый диапазон** | 1–72 |
| **Как калибруем** | Максимальная задержка ретраев в практике |
| **Риск, если завышена** | Рост памяти/хранилища |
| **Риск, если занижена** | Ретрай после TTL создаст дубликат |
| **Связанный инвариант** | INV-006 |
| **Владелец** | Инженерия |

## Рекомендация по конфигу

Все константы — в config (env, yaml, feature store). Логировать изменения. Версионировать при деплое.

```yaml
# example
product:
  min_reflections_for_review: 4

reliability:
  llm_request_timeout_ms: 30000
  llm_max_retries: 2
  idempotency_key_ttl_hours: 24
```
