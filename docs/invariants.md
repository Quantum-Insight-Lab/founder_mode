# Инварианты — Founder Mode

**Основа:** PDA Methodology v1.1, Domain Graph, Acts of Certainty, Uncertainty Map  
**Дата:** 2026-03-09

---

## Принцип (PDA)

Инвариант — то, что должно оставаться истинным всегда. «Физика» системы, первичнее сервисов.

**Практика:** каждый инвариант имеет механизм обеспечения (constraint, тест, валидатор).

---

## INV-001 — Одна рефлексия на пользователя на день

| Поле | Значение |
|------|----------|
| **Invariant ID** | INV-001 |
| **Формулировка** | У пользователя не может быть более одной рефлексии на одну календарную дату |
| **Сфера действия** | DailyReflection, акт 2.2, S1 |
| **Нарушение (пример)** | Две записи DailyReflection для (user_id=1, date=2026-03-09) |
| **Механизм** | unique constraint (user_id, date). Upsert при повторной отправке — перезапись |
| **Слой** | Domain Layer (валидатор перед записью), БД (unique index) |
| **Тесты** | unit: повторное сохранение рефлексии того же дня перезаписывает; property: count(reflections per user per day) ≤ 1 |
| **Мониторинг** | Дубликаты при insert (должно быть 0). Исключения unique constraint |
| **План реакции** | Лог нарушения. Повтор = upsert, не ошибка |
| **Тип** | Идемпотентность |

## INV-002 — Один план на пользователя на неделю

| Поле | Значение |
|------|----------|
| **Invariant ID** | INV-002 |
| **Формулировка** | У пользователя не может быть более одного плана на одну неделю (day_range) |
| **Сфера действия** | WeeklyPlan, Week, акт 1.2 |

| **Слой** | Domain Layer, БД |
| **Тесты** | unit: второй план на ту же неделю обновляет первый |
| **Мониторинг** | Нарушения unique при insert |
| **План реакции** | Upsert по (user_id, week_id) |
| **Тип** | Доменная корректность |

## INV-003 — Обзор только при минимуме данных

| Поле | Значение |
|------|----------|
| **Invariant ID** | INV-003 |
| **Формулировка** | WeeklyReview генерируется только при ≥1 план и ≥1 рефлексия в day_range |
| **Сфера действия** | WeeklyReview, акт 3.1 |
| **Нарушение (пример)** | Обзор сгенерирован при 0 рефлексий или без плана |
| **Механизм** | Валидатор перед вызовом GPT: count(plan for week) ≥ 1, count(reflections in day_range) ≥ 1. Если reflections < min_reflections_for_review — soft prompt (предварительный срез), иначе полный промпт |
| **Слой** | Domain Layer, Review Service |
| **Тесты** | unit: запрос обзора при 0 рефлексий → предупреждение, GPT не вызывается; scenario: 1 план + 1 рефлексия → обзор генерируется (soft) |
| **Мониторинг** | Отклонённые запросы обзора (insufficient_data). Вызовы GPT при нехватке данных = 0 |
| **План реакции** | Показать предупреждение «мало данных». Не вызывать GPT |
| **Тип** | Доменная корректность, причинность |

## INV-004 — Рефлексия не в будущем

| Поле | Значение |
|------|----------|
| **Invariant ID** | INV-004 |
| **Формулировка** | date рефлексии не может быть больше текущей даты |

| **Слой** | Domain Layer |

| **Мониторинг** | Rejected reflections (future_date) |
| **План реакции** | Вернуть ошибку «Рефлексия только за прошедшие дни» |
| **Тип** | Доменная корректность |

## INV-005 — Рефлексии внутри day_range недели

| Поле | Значение |
|------|----------|
| **Invariant ID** | INV-005 |
| **Формулировка** | Рефлексии, включаемые в обзор, должны иметь date в границах day_range (start ≤ date ≤ end) |
| **Сфера действия** | Week, DailyReflection, акт 3.2 |
| **Нарушение (пример)** | В вход обзора попала рефлексия с date вне day_range недели |
| **Механизм** | При сборке WEEKLY_REVIEW_INPUT_SCHEMA фильтровать daily_reflections по day_range |
| **Слой** | Domain Layer, Review aggregation |
| **Тесты** | unit: рефлексия вне day_range не входит в вход; scenario: week Пн–Вс, рефлексия за следующую Пн — не включается |
| **Мониторинг** | Количество рефлексий, исключённых при агрегации |
| **План реакции** | Не включать в вход. Логировать аномалию |
| **Тип** | Доменная корректность, целостность цикла |

## INV-006 — Идемпотентность llm_call

| Поле | Значение |
|------|----------|
| **Invariant ID** | INV-006 |
| **Формулировка** | Повтор запроса к LLM с тем же idempotency_key не дублирует эффект (запись в БД, побочные действия) |
| **Сфера действия** | LLMCall, все вызовы GPT (план, рефлексия, обзор) |
| **Нарушение (пример)** | Ретрай после таймаута создал вторую запись WeeklyPlan |
| **Механизм** | idempotency_key в каждом запросе. Проверка перед записью результата: ключ уже обработан → вернуть сохранённый результат |
| **Слой** | Integration Layer (LLM client), Domain Layer |
| **Тесты** | scenario: два запроса с одним ключом → одна запись, один вызов к API |
| **Мониторинг** | Дедуплицированные запросы (idempotency hit rate). Дубликаты записей = 0 |
| **План реакции** | Повтор → return cached result. Не вызывать API повторно |
| **Тип** | Идемпотентность, воспроизводимость |

## INV-007 — Только владелец изменяет данные

| Поле | Значение |
|------|----------|
| **Invariant ID** | INV-007 |
| **Формулировка** | Пользователь может создавать, читать, изменять только свои Plan, Reflection, Review |
| **Сфера действия** | User, WeeklyPlan, DailyReflection, WeeklyReview |
| **Нарушение (пример)** | User A редактирует Plan User B |
| **Механизм** | Проверка user_id (внутренний UUID) при каждом запросе. Владелец = user_id сущности. API не раскрывает чужие данные |
| **Слой** | API Layer, Domain Layer (authorization) |
| **Тесты** | scenario: запрос к plan другого user_id → 403 / empty |
| **Мониторинг** | Unauthorized access attempts |
| **План реакции** | 403 Forbidden. Логировать |
| **Тип** | Безопасность, права доступа |

## INV-009 — Обзор не выдумывает факты

| Поле | Значение |
|------|----------|
| **Invariant ID** | INV-009 |
| **Формулировка** | Текст обзора опирается только на данные из weekly_plan и daily_reflections. GPT не добавляет фактов, которых нет во входе |
| **Сфера действия** | WeeklyReview, WEEKLY_REVIEW_SYSTEM_PROMPT |
| **Нарушение (пример)** | Обзор упоминает «встреча с инвестором», которой нет в рефлексиях |
| **Механизм** | Промпт: «Не добавляй новых фактов, которых нет во входных данных». Ручной ревью выборочно. v2: structured output + validation |
| **Слой** | Промпт, при необходимости — post-validator |
| **Тесты** | scenario: вход без X → обзор не должен содержать X (выборочная проверка) |
| **Мониторинг** | Feedback «обзор неточен». Ревью качества выхода |
| **План реакции** | Уточнить промпт. Добавить примеры «не выдумывай» |
| **Тип** | Причинность, доверие данным |

## INV-010 — Обзор привязан к плану и рефлексиям

| Поле | Значение |
|------|----------|
| **Invariant ID** | INV-010 |
| **Формулировка** | WeeklyReview всегда имеет causation: создан из конкретного WeeklyPlan и конкретного набора DailyReflection |
| **Сфера действия** | WeeklyReview, derived_from |
| **Нарушение (пример)** | Обзор без ссылки на план. Невозможно воспроизвести, откуда данные |
| **Механизм** | Review хранит week_id (и/или plan_id, reflection_ids). Вход для генерации логируется |
| **Слой** | Domain Layer, Event Core (если есть) |
| **Тесты** | unit: review.week_id совпадает с plan.week_id; review использует те же reflections |
| **Мониторинг** | Обзоры без привязки к плану |
| **План реакции** | Не создавать обзор без валидной привязки |
| **Тип** | Аудит, воспроизводимость |

## Связь с артефактами

- **Domain Graph** → инварианты задают правила для сущностей и связей
- **Acts of Certainty** → акты обеспечивают соблюдение (механизмы в столбце «Механизм»)
- **Constants** → min_reflections_for_review задаёт порог soft/full промпта (если reflections < min → soft prompt). Блокировка обзора — только при 0 рефлексий. План (1 шт.) — захардкожен. См. `constants.md`
- **Uncertainty Map** → инварианты в колонке «Инварианты» соответствуют этим спецификациям
