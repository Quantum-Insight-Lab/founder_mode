# Карта неопределенности — Founder Mode

**Основа:** Product Spec Pack v1.0, PDA Methodology v1.1  
**Дата:** 2026-03-09

---

## Контекст

Founder Mode — бот в Telegram с тремя диалогами: недельное планирование, ежедневная рефлексия, недельный обзор. Цель: измерить движение по недельному плану.

**КТО испытывает неопределенность:** фаундер-сольщик, планирующий неделю «в голове», без структуры для честной оценки.

---

## Uncertainty Map

| Неопределенность | Кто испытывает | Цена ошибки | Частота | Акт определенности | Сигнал/доказательство | Инварианты | Комментарий |
|------------------|----------------|-------------|---------|---------------------|------------------------|------------|--------------|
| **План vs факт: что реально сделал за неделю?** | Фаундер | высокая (иллюзия движения, burnout) | еженедельно | ответы на рефлексию → агрегация в обзор | план + ≥3 рефлексии → GPT-сравнение | обзор только при ≥1 план + ≥3 рефлексии | Ядро продукта. Без акта — «к пятнице не помню» |
| **Какой главный фокус недели?** | Фаундер | высокая (расфокус) | еженедельно | ответы на 6 вопросов планирования | GPT-план с явным фокусом | план сохраняется как эталон для обзора | Воскресенье. Без чёткого фокуса — обзор бессмыслен |
| **Измеримый результат недели — что именно?** | Фаундер | средняя | еженедельно | формулировка в планировании | план содержит критерий done | — | «Конкретный результат» в вопросах планирования |
| **Было ли движение сегодня по главному?** | Фаундер | средняя | ежедневно | Да/Нет в рефлексии | ветка вопросов (Да → что продвинуло / Нет → что остановило) | одна рефлексия = один день | Первый вопрос рефлексии. Разделяет ветки |
| **Что продвинуло / что остановило?** | Фаундер | средняя | ежедневно | текстовый ответ в рефлексии | daily_reflections[].what_moved / what_stopped в схеме входа | — | Схема задаёт поля. Ветка Да → what_moved, Нет → what_stopped |
| **Обзор точен? (план vs факт)** | Фаундер, система | высокая (потеря доверия) | еженедельно | GPT по `WEEKLY_REVIEW_SYSTEM_PROMPT` на входе `WEEKLY_REVIEW_INPUT_SCHEMA` | фокус, статус результата (достигнут/частично/не), что сработало, узкое место, вывод | вход = day_range + weekly_plan + daily_reflections[] | Структурированный вход снижает вариативность GPT |
| **GPT не наговорит общих фраз?** | Фаундер | средняя | при каждом ответе | промпты (WEEKLY_PLAN, DAILY_REFLECTION, WEEKLY_REVIEW) | формат: без советов, без пафоса, плотно, без списков | Response Contract в промптах | Страх из Persona. Промпты ограничивают выход |
| **Рефлексия стоит времени?** | Фаундер | средняя | ежедневно | GPT возвращает ответ на рефлексию | есть «ответ», не просто запись в пустоту | <3 мин на рефлексию | Без обратной связи — «забросил через неделю» |
| **Достаточно ли данных для обзора?** | Система | высокая | при запросе обзора | проверка: ≥1 план + ≥3 рефлексии | предупреждение при нехватке | обзор не показывается без минимума / с предупреждением | Product Decision #5 |
| **Неделя принадлежит одному циклу?** | Система | средняя | при агрегации | day_range (start, end) в `WEEKLY_REVIEW_INPUT_SCHEMA` | план + рефлексии внутри day_range | рефлексия не может относиться к будущему | Схема задаёт границы недели явно |
| **Пользователь редактировал план после создания?** | Система | низкая | редко | версионирование / timestamp | последняя версия плана для обзора | — | v1: возможно редактирование. Аудит — v2 |
| **llm_call воспроизводим?** | Инженерия | средняя | каждый вызов | idempotency_key, trace_id | логирование модели, токенов, latency | повтор запроса с тем же ключом не дублирует эффект | Product Decision #7 |
| **Статус результата недели** | Система, GPT | средняя | при генерации обзора | GPT выбирает: достигнут / частично достигнут / не достигнут | дискретный статус в тексте обзора | — | `WEEKLY_REVIEW_SYSTEM_PROMPT` фиксирует 3 варианта. Без % |
| **Рефлексия не дублируется?** | Система | низкая | при сохранении | одна рефлексия на пользователя на день | unique (user_id, date) | идемпотентность по ключу | Защита от двойного ввода |

## Вопросы, которые продукт должен закрывать

1. **Что я планировал на эту неделю?** → план из воскресенья
2. **Было ли движение по главному фокусу?** → рефлексии + обзор
3. **Что сделал vs план?** → недельный обзор
4. **Стоит ли тратить время на рефлексию?** → GPT-ответ на рефлексию (обратная связь)

## Связь с Product Spec

- **Pain #1** («план был, фактов нет») → неопределённости 1, 2, 6  
- **Pain #2** («нет структуры») → акты определённости: планирование, рефлексия, обзор  
- **Pain #3** («рефлексия скучная») → неопределённость 7, 8

## Артефакты обзора

- **Вход:** `WEEKLY_REVIEW_INPUT_SCHEMA.JSON` — day_range, weekly_plan (current_state, main_focus, weekly_result, why_now, distractions, main_risk), daily_reflections[] (had_movement, what_moved/what_stopped, …)
- **Промпт:** `WEEKLY_REVIEW_SYSTEM_PROMPT.md` — структура вывода (фокус, статус результата, что сработало, узкое место, вывод)
- **Минимум:** ≥1 план + ≥3 рефлексии (Product Decision #5)
